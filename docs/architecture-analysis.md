## 1. Что это

Процедурная космическая игра-исследование, целиком работающая во вкладке браузера на WebGL2.
Никаких готовых 3D-моделей и текстур для космоса: звёзды, планеты, кольца, туманности,
станции, обломки и корпус корабля генерируются из одного целочисленного сида
(`galaxySeed = 20260725`) и шейдятся вручную написанным GLSL.

Сюжет: сорок тысяч лет назад девятьсот обитаемых миров в объёме 80 световых лет замолчали за
четыре дня. Игрок пилотирует исследовательское судно *Pale Seeker*, картографирует системы,
сканирует объекты и настраивается на семь Резонаторов; каждый даёт «Канто» и апгрейд привода,
все семь открывают Апертуру.

Состояние: **завершённый проект, выложенный одним коммитом**. Истории разработки нет, но код
плотно документирован — почти каждый модуль открывается развёрнутым комментарием, где автор
объясняет не только «как», но и «почему именно так» и что ломалось в предыдущих версиях. Это
самая ценная часть репозитория для чтения.

  определился как `medium`.
- **Полностью загрузить сцену не удалось**: встроенная браузер-панель не отображается,
  `document.hidden === true`, поэтому `requestAnimationFrame` не вызывается, а `Game.boot()`
  ждёт кадры между этапами (`await frame()`). Прогресс замер на «seeding the expanse» (5 %).
  Это ограничение среды, а не проблема репозитория — фатальных ошибок в консоли нет, только
  два безобидных предупреждения three (`parameter 'defines' has value of undefined`,
  `THREE.Clock` deprecated). Чтобы увидеть игру, нужно открыть панель браузера или
  `http://localhost:5173` в обычном Chrome.

## 4. Поток выполнения

```
index.html  — весь UI-оверлей заранее в DOM (boot-экран, HUD, звёздная карта, архив, тач)
    └─ src/main.js
         ├─ отсев телефонов (не «урезанная сборка», а вежливый отказ) + гейт на WebGL2
         ├─ new Game(canvas, progress)  →  Engine → PostFX; Input
         ├─ await game.boot()           →  прогресс-бар с текстовыми стадиями
         │     galaxy (generateGalaxy, 14 систем)
         │     → nebula cubemap (bakeNebulaCube) → PMREM-окружение
         │     → starfield (14k звёзд) → Ship (процедурный корпус)
         │     → interiorScene: отдельная сцена + своя камера + RoomEnvironment
         │     → loadInteriorAssets (glTF+WebP) → buildInterior → Player, Cockpit
         │     → loadSystem(0): звезда, планеты, луны, пояса, аномалии, станции, трафик
         ├─ кнопка WAKE → HUD, аудио, вступительные реплики
         └─ tick(): game.update(dt) → engine.render(interiorScene?, interiorCam) → engine.adapt(dt)
```

`?record=N` заменяет цикл на ручной шаг `window.__step(n)` с фиксированным dt — чтобы захват
видео шёл ровно, а не с рывками (`tools/trailer.mjs`).

Кадр `Game.update(dt)` (по разделителям в `Game.js`): клавиши UI → орбиты → ввод от первого
лица и взаимодействие → полётная модель → автопилот → **пересчёт плавающего начала координат**
→ позиция члена экипажа → камера → сканирование.

## 5. Ключевые технические решения

**Плавающее начало координат + логарифмическая глубина.** 1 юнит = 1 км, корабль длиной
0.1 юнита живёт в системе размером в миллионы юнитов. Корабль всегда в (0,0,0), всё остальное
переставляется относительно него каждый кадр. Кастомные `ShaderMaterial` подключают лог-глубину
вручную через чанки `LOGD_*` из `src/gfx/glsl/noise.js`; забыть — значит получить z-fighting
планеты с её же атмосферой.

**Две сцены, два соглашения о глубине.** Космос — лог-буфер, ближняя плоскость в метрах,
дальняя 6e7. Земля (`Surface.js`) — обычная проекция, near 0.5 м, far 50 км: `gl_FragDepth`
убивает early-Z, что на tile-based GPU стоит очень дорого (замеры автора: 29.3 → 21.2 мс).
Кабина — третий случай: отдельная сцена, своя камера, лог-глубина снята со всех материалов.
`PostFX.captureDepth` нормализует то, что владеет кадром, в один общий R32F-буфер, чтобы
AO не знал про три кодировки.

**Планеты запекаются, а не считаются.** Двадцать октав симплекса на пиксель на кадр
неподъёмны, поэтому каждый твёрдый мир один раз рендерится в кубмапу: RGB — линейное альбедо,
A — высота рельефа. В рантайме это три выборки текстуры плюс освещение. Ближайший мир
перезапекается в 1024²/грань, остальные держатся на 256² (`_updateBakeLOD`, `_bakeStep` —
запекание размазано по кадрам). Кубмапа, а не equirect — нет ни полюсного схлопывания, ни шва.

**Атмосфера** — single-scattering raymarch по сферической оболочке в объектном пространстве
планеты, коэффициенты Рэлея взяты из реальных оптических глубин (~0.05/0.10/0.23 в зените),
плюс мягкая планетарная полутень на луче света, чтобы сумерки не обрывались линией.

**Земля — отдельная сцена** (`Surface.js`, 6392 строки, самый интересный файл). Радиальная
сетка с экспоненциально растущими кольцами, смещённая тем же законом рельефа, что и орбитальное
запекание, загнутая вниз по реальному радиусу планеты. Тени — геометрический raymarch по
высотному полю **в вершинном шейдере** (70 тыс. маршей вместо 6 млн, без shadow map).
Центральная идея файла: у высотного поля есть параметр `lod` — шаг в метрах, с которым его
сейчас будут сэмплировать, — и поле просто не содержит частот выше него. Меш, марш теней и
камни передают каждый свой шаг, поэтому никто ни с кем не расходится.

**Один «конструктор» на весь рукотворный мир** (`gfx/greeble.js`). Один закон швов панелей,
одно выветривание, один rim-term, пять базовых материалов — и корпус игрока, и фрахтовики, и
станции, и обломки Хора surfaced им же. Детали запекают трансформ в геометрию и свариваются по
материалу, поэтому линии панелей идут непрерывно через границы частей, а сотня деталей стоит
шесть draw-call'ов. Там же `HULL_LIGHT` — аналитическая замена IBL: в глубоком космосе
окружение это ровно две вещи, звезда и ближайший мир, обе описываются диском и пустотой.

**Трафик по расписанию, а не симуляция** (`Fleet.js`). Корабли идут по аналитическим путям,
привязанным к часам, поэтому после фолда, перезагрузки системы или двухминутной паузы они
ровно там, где должны быть. Каждый несёт «маяк» — квад, размер которого пересчитывается из
глубины так, чтобы занимать константные несколько пикселей: 60 м корпуса в 4 млн км — сильно
меньше пикселя, а движущаяся искра и есть то, что делает систему обитаемой.

**Пост-обработка** (`PostFX.js`) руками, ~20 полноэкранных проходов: линейная глубина → AO с
билатеральным блюром → bright prefilter → 6 уровней dual-filter bloom → анаморфный streak →
god rays и блики → композит (radial blur, хроматическая аберрация внутри сэмплера, AgX
tonemap, зерно, дизеринг) → FXAA. Автоэкспозиция целиком на GPU: редукция яркости 64²→8²→1²
и ping-pong адаптация. Метрика — **корень из среднего, а не логарифм**: кадр в космосе на 90 %
чёрное небо, и лог околонулевых значений утягивает среднее в ноль, пересвечивая всё.

**Производительность — за счёт разрешения, не за счёт фич** (`Engine.adapt`). Контроллер следит
за частотой кадров и двигает масштаб рендера между 0.62× и 2×. Тонкости, которые видно по
комментариям: старт с нативного разрешения и подъём вверх (а не спуск с потолка), прогрев 5 с
перед первым решением, кулдаун 2 с между изменениями, отложенный resize в начале кадра (иначе
один полностью чёрный кадр на каждое изменение), симметричные скорости вверх и вниз.

**Диагностические флаги URL**: `?logdepth=0`, `?msaa=0`, `?post=0`, `?ao=0`, `?q=low|medium|high`,
`?record=N`. Часть из них намеренно портит картинку — они существуют, чтобы браузер, который
нельзя профилировать удалённо, мог отбисектить тот, кто сидит перед ним.

## 6. Игровые системы

- **Режимы**: `walk` (от первого лица внутри корпуса), `pilot` (в кресле), `exterior`
  (камера преследования). Внутренности — полноценная сцена с glTF-китом, PBR-материалами,
  контактными тенями и интерактивными станциями.
- **Сканирование**: удержание `F` на цели в прицеле, дальность зависит от типа тела и апгрейдов
  (`scanRangeFor`, `updateScan`, `completeScan`), результат уходит в Архив/Кодекс.
- **Фолд-привод**: скорость масштабируется расстоянием до ближайшей массы, поэтому подход сам
  тормозит и выбрасывает у поверхности (`foldFloor`, `toggleFold`); межзвёздный прыжок
  запускается со звёздной карты и тратит заряд по дистанции (`hyperjump`).
- **Посадка**: отдельный конвейер `canLand → beginEntry → _prepareGround → _buildGround →
  _stageGround → _finishGround`, прикрытый непрозрачной облачной пеленой (`CLOUD_IN 0.70 /
  CLOUD_OUT 2.3 / CLOUD_OPAQUE 0.995`) — под ней меняется сцена, соглашение о глубине и
  ближняя/дальняя плоскости. Пока пелена непрозрачна, сцена вообще не рисуется
  (`Engine.skipScene`) — замеренный кадр смены материалов стоил 159 мс.
- **Прогрессия**: `directives.js` — цепочка из одной активной директивы за раз; первые четыре
  шага незаметно учат садиться в кресло, брать цель, сканировать и фолдить. Награды —
  Канто, найденный лог или измеримый апгрейд (`UPGRADES`: скорость сканирования, регенерация
  привода, тяга, обшивка, дальность сенсоров).
- **Режиссура**: `Director.js` — катсцена это *камера*, а не анимация. Мир продолжает
  симулироваться, каждый кадр шота — функция нормализованного времени, возвращающая позицию
  глаза, точку взгляда и фокусное расстояние; якоря разрешаются вживую относительно субъекта.
- **Звук**: `Audio.js`, всё синтезируется. Музыка — фразами с паузами между ними, каждый голос
  создаётся, огибается, останавливается и выбрасывается; ничего не тянется бесконечно.

## 7. Инструментарий

`tools/` — это отдельная, довольно необычная часть проекта: 30+ Node-скриптов, которые гоняют
настоящий headed Chromium с GPU-растеризацией против `npm run dev`.

- Проверка: `play.mjs` (17 утверждений про полёт, скан, фолд, прыжок), `smoke.mjs`, `boot.mjs`.
- Съёмка: `survey.mjs` (скриншот каждой сцены + fps/draws), `shot.mjs`, `capture.mjs`,
  `tour.mjs`, `trailer.mjs`, `splash.mjs`, `mapshot.mjs`.
- Анализ картинки: `levels.mjs` (тоновая статистика), `imgdiff.mjs`, `sheet.mjs` (контактный
  лист), `chroma.mjs`, `judgeset.mjs`.
- Профилирование: `perfprobe.mjs`, `passcost.mjs`, `drawcost.mjs`, `tiers.mjs`, `leaks.mjs`.
- `tools/interior_bake/*.py` — пронумерованный пайплайн запекания интерьера в Blender
  (геометрия тайлов → запекание → композит → кит → сборка), плюс `bake_terrain.py`.

`boot.mjs` существует потому, что dev-сервер перезагружается на любую правку исходника, и
захват, начавшийся до перезагрузки, спокойно снимает титульный экран с правдоподобным fps
рядом. Он проверяет, что оверлей действительно исчез, и начинает заново, если нет.

Бонус: репозиторий несёт собственный скилл для Claude Code —
`.claude/skills/blender-hardsurface/` с рабочим кодом для управления Blender через
BlenderMCP-сокет (лофт-и-выемка, процедурные материалы, освещение глубокого космоса).

## 8. Наблюдения

**Сильные стороны**

- Комментарии объясняют причину, замеры и то, что сломалось раньше. Это редкость и главная
  причина, по которой репозиторий стоит читать целиком.
- Одна прод-зависимость. Всё остальное написано руками и потому взаимосогласовано.
- Инструментарий превращает «выглядит плоско» в «0.00 % пикселей клиппится, 99-й перцентиль 165».
- Честная позиция по мобильным: отказ с внятным сообщением вместо урезанной сборки.

**Риски и на что смотреть, если захочется что-то менять**

- Файлы по 2–6.4 тыс. строк (`Surface.js`, `Game.js`, `Station.js`) — читать целиком не стоит,
  ориентироваться по комментариям-разделителям `/* ---- ... */`, они там расставлены аккуратно.
- Ни одного автотеста в привычном смысле; вся проверка — визуальная, через Playwright и
  запущенный dev-сервер. Изменение шейдера верифицируется только скриншотом.
- Нет линтера, типов, CI. Один коммит — `git blame` бесполезен.
- Три соглашения о глубине (лог / обычная / кабина) — самое хрупкое место. Любой новый
  `ShaderMaterial` обязан либо подключить `LOGD_*`, либо явно от них отказаться, иначе z-fight.
- Бандл 1.67 МБ одним чанком; код не разделён.
- `npm run splash` использует macOS-утилиту `sips` — на Windows не работает.
- Глобальное состояние: `window.__game`, `window.__hullLight`, `window.__step` — это входные
  точки для `tools/`, а не отладочный мусор; удалять нельзя.

**Точки входа для правок**

- Баланс и прогрессия → `src/game/directives.js`, `src/game/lore.js` (данные, не логика).
- Внешний вид любого рукотворного объекта → `src/gfx/greeble.js`.
- Постобработка и тон → `src/gfx/PostFX.js`.
- Состав и параметры вселенной → `src/world/generate.js` (палитры, классы звёзд, орбиты).
- Ландшафт → `src/world/Surface.js`, начиная с описания `lod` в шапке файла.
